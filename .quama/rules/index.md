## 规则使用说明

### 适用范围
- 所有项目成员必须遵守这些规则
- 所有代码和文档必须符合这些标准
- 所有流程必须遵循这些规范

### 规则优先级
1. **强制规则**：必须遵守，违反将导致严重后果
2. **推荐规则**：强烈推荐，违反需要说明理由
3. **建议规则**：建议遵守，可根据实际情况调整

### 规则更新
- 规则定期评审和更新
- 更新需要团队讨论和审批
- 更新后需要通知所有成员

### 规则执行
- 规则通过代码审查、文档评审等方式执行
- 违反规则需要及时纠正
- 规则执行情况定期回顾

## 规则设计理念

### 基于Ponytail的优化
这些规则借鉴了Ponytail项目的优秀实践，特别是：
1. **最小化原则**：只做必要的事情
2. **质量第一**：永远不为速度牺牲质量
3. **透明沟通**：所有重要决策必须有记录
4. **持续改进**：定期回顾，持续优化

### 适应团队需求
这些规则根据团队实际情况进行了调整：
1. **中文书写**：所有规则使用中文，便于理解
2. **结构清晰**：规则结构清晰，便于查找
3. **实用导向**：规则实用导向，便于执行
4. **灵活调整**：规则可根据项目特点灵活调整

### 符合工程规范
这些规则符合软件工程规范：
1. **系统化**：覆盖软件开发全过程
2. **标准化**：遵循行业标准和最佳实践
3. **可度量**：规则执行情况可度量
4. **可改进**：规则可持续改进
